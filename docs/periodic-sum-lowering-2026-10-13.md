# Generic periodic byte sum lowering and ARM64 cost policy

Compiler 635011f implements a complete-function pattern without benchmark/function-name checks; 36e6707 bounds parameter/name matching. A function must have integer parameters/result, exactly four distinct integer locals (cached standard-view length, zero index/sum, offset%P+1), a pure byte-weight loop with exactly the index/weight updates and reset to one, and sole return sum. P is a literal in 1..32. Calls/observers, aliased construction, live index/weight results, modified accessors/indices, extra control flow and coroutine storage are rejected. Imported APIs are resolved against the current standard library and user overrides are rejected.

The fast prefix requires a live immutable view/data, representable cached length and positive starting weight. It computes the same P cyclic weights, consumes P-byte blocks and a bounded tail, and returns the same modulo-2^64 sum. The original body is ALWAYS emitted after the guarded prefix. Every count/index update is bounded, products are <=255*32=8160 and only the sum escapes. Null handles/data, nonpositive weights and unrepresentable lengths retain the original body. Zero-length valid views return zero in either path. Public APIs, allocation/lifetime and JavaScript code remain unchanged.

Numeric regression checks 313 UTF-8/ASCII/zero-handle/offset/period-boundary combinations at -O0/-O3 with UBSan, inline and ABI-only headers, plus JavaScript. Periods1/3/13/32 and INT64_MIN/MAX offsets are included. Matcher tests use independent function/variable names, reject11 unproven shapes, verify parameter-name collisions, and verify bounded fallback for64 conflicting names. The [OMO implementation review](periodic-sum-omo-review-2026-10-13.md) records scope and corrections.
