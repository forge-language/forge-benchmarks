# Guarded periodic scan and positive reciprocal screening

Status: numerical correctness passed; performance pending. Explicit generated-C experiment on current compiler d4c632b, not a compiler feature. The workflow supports a current-compiler control so incremental change can be measured against identical unmodified producers, with matched Rust and the same per-run SDK.

The LCG range guard and bounded positive modular arithmetic retain the prior proof. The prime helpers now request inline expansion so the C optimizer can see constant bases and caller bounds. Positive modular products remain <=INT64_MAX. On targets with int128 outside ARM64, the prefix caches ceil(2^64/d) and computes high multiply, a quotient product, and at most one correction. For 0<=n<=INT64_MAX and d<=3037000499, q is exact or one high and q*d<=n+d<2^64, so neither the quotient product nor correction wraps. ARM64/no-int128 use checked-by-entry unsigned hardware remainder instead. This is a measured-policy candidate, not a universal CPU cost claim. All guard-failing inputs retain the original checked bodies.

The scan prefix uses a valid live immutable view with cached len<=INT64_MAX and initial weight=offset%13+1 in 1..13. It precomputes the same 13 cyclic weights, consumes complete 13-byte blocks, then at most 12 tail bytes. Each unsigned byte*weight is <=3315. Unsigned 64-bit accumulation and final Forge bit reinterpretation equal the original wrapping signed sum. Advancing only when count-i>=13 preserves i<=count and keeps every i+j in range; tail weight indices are <13. Negative/zero initial weights, zero handles, null data and unrepresentable lengths use the original body. No new callbacks, arena reset, allocation or mutation occurs. The original source algorithms and Rust control are unchanged; recognizing this general proof in a compiler remains future work.

The extended independent test checks 671 inputs, including byte values above 127, every 13-byte block/tail boundary, full-width seeds and signed offsets, and previous arithmetic/trap cases. Original/candidate at -O0/-O3 pass under UBSan in both native-int128 and forced no-int128 configurations (5368 executions total). The latter exercises the same hardware-remainder branch chosen on ARM64; native cross-OS measurement still must verify actual target compilation and profitability.

No speed claim is made. The preceding range-kernel matrix is retained as evidence that correctness and an optimizer hint do not establish a useful gain. Further results, proof review and exact source/SDK/binary hashes must stay separate from shipped compiler performance.
