# Forge 성능 개선·검증 결과

정식 컴파일러 `a750b60`을 생성 C 수정 없이 측정했다. 대표 CPU 작업 5종의 Linux·macOS·Windows 결과 30개 모두 Rust 처리량의 110% 기준을 통과했다. Linux HTTP에서는 p99 1초 이하·오류 0건 기준으로 11,264개 동시 요청 코호트를 검증했다. 실제 애플리케이션 사용자 수와 모든 프로그램의 성능을 보장하는 결과는 아니다.

| Linux CPU 가장 낮은 개별 95% 신뢰구간 하한 | Rust의 약 137.58% | 해당 OS의 측정 행 중 최소값 |

CPU 신뢰구간은 각 행의 개별 구간이다. 30개 행 전체를 동시에 보장하는 신뢰구간이나 언어 전체의 성능 보장이 아니다. OS별 CPU·가상화·컴파일러 환경이 달라 OS 자체의 인과 효과도 분리하지 않았다. 기존 Forge 대비 모든 작업이 10% 빨라졌다는 주장도 하지 않는다. [정식 컴파일러 OS별 전체 결과와 실행 증거](bounded-modpow-native-cross-os-2026-10-14.md), [로컬 60그룹 결과](bounded-modpow-generic-full-60-2026-10-14.md)에 모든 행과 해시를 보관했다.

HTTP 최대치는 탐색한 시험 크기 중 모든 반복이 기준을 통과한 크기다. 11,264~12,288 사이의 1,024개 구간을 모두 탐색하지 않았으며 절대 한계나 지속 부하의 수용 인원을 뜻하지 않는다. 서버가 실제 수락한 연결 수를 세는 계측도 아니다. 단일 Python 측정기·루프백 TCP·커널의 비용을 포함한 결과이며, 두 구현의 HTTP 처리량 차이를 일반화할 수 없다. HTTP는 Linux에서만 측정했다. [V4.1 수용량 보고서](http-cohort-capacity-2026-10-14.md)에 버전별 원시 기록과 실패를 보관했다. 과거 128,000 완료 요청을 동시 사용자 수로 해석했던 주장은 철회한 상태다.

코드 개선은 기존 산술·소유권·공개 ABI 동작을 유지하는 범위에서 진행했다. 컴파일러에는 엄격한 AST·바인딩 증명으로 확인한 모듈러 거듭제곱만 빠르게 생성하고, 범위 밖에서는 기존 검사 경로를 사용하도록 했다. 스캔·이름 재시도 횟수를 제한하고 라이브 값·부수 효과·코루틴 등 증명이 성립하지 않는 형태를 거부한다. 런타임에서는 스케줄러·코루틴·이벤트 처리와 Windows 임시 경로 예약을 개선했고, 표준 라이브러리에서는 문자열 빌더 소유권 이전과 Windows 파일 디스크립터·stat 구조체 호환성을 정리했다. 이는 확인된 경로의 수정이며 포괄적인 보안 인증은 아니다.

OMO에서 실제 위임한 하위 에이전트 6개의 산술 증명·AST·C 이식성·테스트 범위·HTTP 계측·OS별 증거 검토를 완료했다. 초기 모델 라우팅 실패와 재시도 기록도 보관했고, 실패한 호출을 완료된 검토로 세지 않았다. 검토 지적에 따라 경계값·트랩·모듈/라이브러리·이름 충돌 테스트와 자료 설명을 보강했다. [구현 증명·검토 기록](bounded-modpow-lowering-2026-10-14.md)을 참고할 수 있다.

그 뒤 같은 HTTP 하위 에이전트에 요청한 추가 코호트 검토는 최종 답변이 도착하지 않아 중단했다. 이를 완료된 검토로 집계하지 않았으며 [요청·부분 실행·중단 상태](omo-cohort-followup-status-2026-10-14.json)를 별도로 보관했다. V4.1의 검증은 실행한 테스트와 원시 측정 기록에 근거한다.

최종 컴파일러 전체 22개 CTest 스위트가 통과했다. 이름을 표시한 별도 검증에서도 컴파일러 40개·산술 36개 테스트가 통과했다. 새 HTTP 측정기의 8개 오류/경계 테스트와 두 서버의 일반·대형·분할 헤더 검증이 통과했다. Windows 네이티브 임시 파일·파일 시스템 테스트는 OS별 실행 두 개 모두 통과했다. 관측 중 발생한 HTTP 포트 충돌은 원래 실패 기록을 보존하고 V4.1에서 와일드카드 주소에 맞는 포트를 선택하도록 고쳤다. 수정 후 48개 시험에는 서버 시작 실패가 없었다.

구현·보안/이식성·측정기·검증 보고서를 나눠 커밋하고 각 저장소에 푸시했다. 최종 소스는 Forge `a750b60`, runtime `dcbb192`, stdlib `6aa2866`이며, 벤치마크 저장소에는 OS별 보고서·수용량 측정기·포트 선택 수정·원시 증거가 별도 커밋으로 남는다. 기존 실패·기각된 최적화·원시 자료는 삭제하지 않았다.
